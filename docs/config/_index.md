# `config/` — обзор пакета

> 1 экран: что лежит в `config/`, кто с кем связан, куда идти за деталями.

## Назначение пакета

Единая точка конфигурации системы. Все настройки читаются из переменных
окружения/`.env` файла и НИКОГДА не хардкодятся в коде ролей/инструментов
— это единственный модуль, который знает про имена env-переменных.

## Файлы пакета → документы

| Файл кода | Документ |
|---|---|
| `config/__init__.py` | — (пустой файл-маркер) |
| `config/settings.py` | `settings.md` |

Один содержательный файл — дробить `settings.md` дальше некуда.

## Зависимости

```
.env файл  ──►  Settings (pydantic_settings.BaseSettings)
                        │
                        ▼
        get_settings() (модульный синглтон)
                        │
     ┌──────────────────┼───────────────────────┐
     ▼                  ▼                       ▼
Orchestrator     llm/factory.py           roles/*.py (пороги, лимиты)
(../orchestrator  (создание клиентов)     vault/*.py (пути, embedding)
/state_machine.md)                        staging/*.py, cli/*.py
```

## Кто вызывает

Практически весь проект читает `Settings` через `get_settings()`. Прямые
потребители перечислены в сводной таблице `settings.md` в конце файла.

## Порядок чтения

Один файл — `settings.md`, разбит на смысловые блоки (провайдер, Groq
rate-limiting, Vault, Synthesizer/Critic, прочее) — можно читать точечно по
нужному блоку, не всё целиком.
