# Документация цикла LLM-вызова. Часть 2: `llm/common.py` — провайдер-нейтральный фундамент

> Продолжение Части 1 (`docs_llm_cycle_part1_orchestrator.md`). Этот файл описывает
> `llm/common.py` — модуль, от которого зависит `llm/groq_client.py` (импортирует
> из него иерархию исключений и утилиты оценки токенов). Части 3–4 (следующие
> сообщения) опишут сам `GroqClient` и его внутренние вспомогательные классы
> (`TokenRateLimiter`, `TokenEstimateCalibrator`, `CacheObservability`).

---

## 1. Назначение модуля

`llm/common.py` — код, общий для ВСЕХ провайдеров (`GroqClient`, `OpenRouterClient`,
любой будущий `<provider>_client.py`). Правило проекта: роли (`roles/*.py`) и общий
код (`llm/chunking.py`) должны ловить **только** типы исключений отсюда
(`LLMRateLimitError`/`LLMSchemaError`/`LLMPromptTooLargeError`), никогда
провайдер-специфичные классы напрямую (`GroqRateLimitError` и т.п.) — это и есть
"контракт по ошибкам" в дополнение к методам `llm/base.py::LLMClient`.

---

## 2. Иерархия исключений

```
Exception
 └── LLMError
      ├── LLMRateLimitError
      ├── LLMSchemaError
      ├── LLMPromptTooLargeError
      └── LLMProviderOverloadedError
```

### 2.1. `class LLMError(Exception)`

**Описание.** Общий базовый класс для всех ошибок, поднимаемых любым клиентом,
реализующим `llm/base.py::LLMClient.generate_structured()`. Сам по себе никогда
не поднимается напрямую — только через подклассы ниже.

**Параметры конструктора:** стандартные для `Exception` (позиционное сообщение).
**Исключения, которые сам поднимает:** нет (базовый класс).

### 2.2. `class LLMRateLimitError(LLMError)`

**Описание.** 429 / rate limit от API провайдера, устойчивый после retry на
уровне клиента (т.е. это уже после исчерпания встроенного `tenacity`-ретрая
в `GroqClient._call_with_retry`). На верхнем уровне (в `generate_structured`
каждого конкретного клиента) оборачивается в
`orchestrator.budget.LLMFreeLimitReached` — единственное место, которое
остаётся провайдер-специфичным по смыслу обработки.

**Конкретные подклассы в проекте:** `GroqRateLimitError` (`llm/groq_client.py`),
`OpenRouterRateLimitError` (`llm/openrouter_client.py`).

#### `__init__(self, message: str, retry_after: float | None = None)`

**Описание.** Расширяет стандартный конструктор `Exception` полем `retry_after` —
временем в секундах, которое API попросил подождать (если оно было явно указано
в теле ошибки).

**Параметры:**

| Имя | Тип | Назначение |
|---|---|---|
| `message` | `str` | Текст ошибки (передаётся в `super().__init__`). |
| `retry_after` | `float \| None` | Секунды до следующей попытки, распарсенные из текста ошибки API (см. `parse_retry_after` ниже). `None`, если API не указал явно. |

**Возвращаемое значение:** — (конструктор).
**Атрибуты после инициализации:** `self.retry_after`.

### 2.3. `class LLMSchemaError(LLMError)`

**Описание.** Модель вернула JSON, невалидный по `response_model` даже после
repair-эвристик (`repair_json`, см. §4). Вызывающий код (например,
`roles/extractor_critic.py`) может отреагировать уменьшением размера батча
(рекурсивное деление пополам), а не просто повторным тем же запросом —
поскольку повтор с тем же промптом с высокой вероятностью снова даст ту же
проблему (модель "не справляется" с объёмом/сложностью батча).

**Конкретные подклассы:** `GroqSchemaError`, `OpenRouterSchemaError`.
**Конструктор:** стандартный (`Exception.__init__`), дополнительных полей нет.

### 2.4. `class LLMPromptTooLargeError(LLMError)`

**Описание.** Промпт + система + ожидаемый output превышают доступный бюджет
контекста/TPM. Поднимается ДО (проактивно) или ВМЕСТО (реактивно, по 413 от API)
сетевого вызова — вызывающий код должен порезать текст на чанки
(см. `llm/chunking.py::split_items_into_batches`).

**Конкретные подклассы:** `GroqPromptTooLargeError`, `OpenRouterPromptTooLargeError`.
**Конструктор:** стандартный.

**Важно:** этот класс **намеренно НЕ входит** в список триггеров failover в
`llm/router.py::_FAILOVER_TRIGGERS` — слишком большой промпт не повод пробовать
другую модель того же класса задач (у них обычно похожий контекст), это должен
решать вызывающий код (чанкинг), а не переключение модели.

### 2.5. `class LLMProviderOverloadedError(LLMError)`

**Описание.** Апстрим-провайдер модели временно перегружен (например,
OpenRouter `503`/`provider_overloaded`). Retryable и failover-triggering —
это не проблема качества ответа модели, а временная недоступность
инфраструктуры за конкретной моделью-кандидатом. **Не используется `GroqClient`
напрямую** (у Groq нет промежуточного апстрим-провайдера как у OpenRouter) —
упомянут здесь только потому, что это часть общей иерархии `llm/common.py`.

**Конкретный подкласс:** `OpenRouterProviderOverloadedError`.
**Конструктор:** стандартный.

## 3. JSON-repair

### 3.1. `WORD_DIGITS: dict[str, str]`

**Описание.** Константа-словарь: числа словами на английском → строковые цифры
(`{"zero": "0", "one": "1", ..., "ten": "10"}`). Нужна, потому что слабые
бесплатные модели иногда подставляют вместо цифр в JSON текст вида `"0. Nine"`
вместо `0.9` (реальный наблюдавшийся баг в логах проекта).

**Тип:** `dict[str, str]`, не функция/класс — константа модуля.

### 3.2. `repair_json(raw: str) -> str`

**Описание.** Чинит два наиболее частых способа, которыми слабые модели ломают
JSON-ответ:
1. markdown-обёртку (` ```json ... ``` `);
2. число словами после десятичной точки (`"0. Nine"` / `"0.Nine"` → `"0.9"`).

Не гарантирует валидность результата — вызывающий код (`GroqClient._parse_with_repair`)
обязан обернуть повторный `model_validate_json` в `try/except`.

**Параметры:**

| Имя | Тип | Назначение |
|---|---|---|
| `raw` | `str` | Сырой текст ответа модели, который не прошёл `model_validate_json` с первой попытки. |

**Возвращаемое значение:** `str` — исправленный (или неизменённый, если исправлять
было нечего) текст.

**Исключения:** не поднимает — чисто текстовые regex-преобразования.

**Внутренняя логика:**
- убирает начальные/конечные ```` ``` ```` и опциональный маркер `json` через `re.sub`;
- ищет паттерн `(\d)\.\s*([A-Za-z]+)\b` и заменяет найденное английское слово-число
  (если оно есть в `WORD_DIGITS`) на цифру после точки. Если слово не найдено в
  словаре — совпадение оставляется без изменений (`match.group(0)`).

## 4. Распознавание типа ошибки по тексту

Все функции ниже работают с текстовым представлением исключения (`str(exc)`),
т.к. и Groq, и OpenRouter в проекте построены поверх одного и того же SDK-пакета
`openai`, но конкретные классы исключений этого SDK не всегда однозначно
соответствуют HTTP-коду — поэтому используется грубый, но надёжный текстовый поиск.

### 4.1. `is_rate_limit_error(exc: Exception) -> bool`

**Описание.** Определяет, похоже ли исключение на HTTP 429 / rate limit,
по вхождению маркеров в текст (без учёта регистра).

**Параметры:**

| Имя | Тип | Назначение |
|---|---|---|
| `exc` | `Exception` | Пойманное исключение (обычно от `openai`-клиента или произвольный `RuntimeError`). |

**Возвращаемое значение:** `bool` — `True`, если в `str(exc).lower()` встречается
`"429"`, `"rate limit"` или `"rate_limit"`.

**Исключения:** не поднимает.

**Где используется:** `GroqClient._call_with_retry` (реальный сетевой сбой →
`GroqRateLimitError`), `OpenRouterClient._call_with_retry` аналогично.

### 4.2. `is_request_too_large_error(exc: Exception) -> bool`

**Описание.** Определяет, похоже ли исключение на HTTP 413 (Request Entity Too Large).

**Параметры:** `exc: Exception`.

**Возвращаемое значение:** `bool` — `True`, если в тексте есть `"413"`,
`"request_too_large"` или `"request entity too large"`.

**Исключения:** не поднимает.

**Где используется:** `GroqClient._call_with_retry` — превращает такую ошибку
в `GroqPromptTooLargeError`.

### 4.3. `parse_retry_after(message: str) -> float | None`

**Описание.** Пытается извлечь число секунд из фразы вида
`"Please try again in 10.02s"` (типичный формат сообщения Groq API при 429).

**Параметры:**

| Имя | Тип | Назначение |
|---|---|---|
| `message` | `str` | Текст ошибки API. |

**Возвращаемое значение:** `float | None` — число секунд, если паттерн найден и
успешно парсится как `float`; иначе `None`.

**Исключения:** не поднимает (внутренний `ValueError` от `float(...)` перехватывается
и превращается в `None`).

**Регулярное выражение:** `_RETRY_AFTER_RE = re.compile(r"try again in\s+([\d.]+)\s*s", re.IGNORECASE)`.

**Где используется:** `GroqClient._call_with_retry` — если Groq вернул явный
retry-after, вызывается `self._limiter.force_wait(retry_after)` перед
`self._limiter.register_rate_limit_hit()`.

## 5. Оценка числа токенов без внешних зависимостей

Это **грубая эвристика** (не настоящий токенайзер) — проект намеренно не тянет
зависимость на `tiktoken`/`transformers` только ради подсчёта токенов. Коэффициенты
подобраны отдельно для кириллического и латинского текста, т.к. кириллица кодируется
BPE-токенайзерами существенно менее эффективно (больше токенов на символ).

### 5.1. `chars_per_token(text: str, *, cyrillic_ratio_threshold: float = 0.3, cyrillic_chars_per_token: float = 2.3, latin_chars_per_token: float = 4.0) -> float`

**Описание.** Определяет, какой из двух коэффициентов "символов на токен"
применить к тексту, по доле кириллических символов в нём.

**Параметры:**

| Имя | Тип | Назначение |
|---|---|---|
| `text` | `str` | Текст, для которого нужен коэффициент. |
| `cyrillic_ratio_threshold` | `float` (keyword-only) | Порог доли кириллицы, выше которого текст считается "кириллическим". Дефолт `0.3` (30%). |
| `cyrillic_chars_per_token` | `float` (keyword-only) | Коэффициент для кириллического текста. Дефолт `2.3`. |
| `latin_chars_per_token` | `float` (keyword-only) | Коэффициент для латинского/смешанного текста. Дефолт `4.0`. |

**Возвращаемое значение:** `float` — один из двух переданных коэффициентов.
Если `text` пустой — возвращается `latin_chars_per_token` (безопасный дефолт).

**Исключения:** не поднимает.

**Логика:** считает символы, для которых `"а" <= ch.lower() <= "я" or ch.lower() == "ё"`
(диапазон кириллицы + отдельно `ё`, т.к. она вне алфавитного диапазона `а-я`),
делит на `len(text)`, сравнивает с порогом.

**Где переопределяются коэффициенты:** `GroqClient` читает их из
`settings.groq_chars_per_token_cyrillic` / `groq_chars_per_token_latin` /
`groq_cyrillic_ratio_threshold` (см. Часть 3) — то есть дефолты здесь являются
"хардкодом на случай отсутствия Settings", а не единственным источником истины.

### 5.2. `estimate_tokens(text: str, *, cyrillic_ratio_threshold: float = 0.3, cyrillic_chars_per_token: float = 2.3, latin_chars_per_token: float = 4.0) -> int`

**Описание.** Главная публичная функция оценки токенов — делит длину текста
на подобранный `chars_per_token(...)` коэффициент.

**Параметры:** те же четыре, что у `chars_per_token` (сигнатура идентична).

**Возвращаемое значение:** `int` — `int(len(text) / cpt) + 1`. Добавление `+1`
гарантирует ненулевую оценку даже для очень короткого непустого текста и грубо
компенсирует токены-разделители/служебные токены. Для пустого `text` возвращает `0`.

**Исключения:** не поднимает.

**Кто вызывает:**
- `llm/chunking.py::split_items_into_batches` — оценивает `render_item(item)` и
  `static_overhead_text` при батчинге списков под бюджет клиента.
- `GroqClient._estimate_tokens` — тонкая обёртка, которая подставляет коэффициенты
  из `Settings` (см. Часть 3).
- `OpenRouterClient.available_prompt_budget_tokens` — с дефолтными коэффициентами
  (не настраивается из Settings для OpenRouter).

## 6. Сводная таблица: что из `llm/common.py` использует именно `GroqClient`

| Импортируемое имя | Как используется в `llm/groq_client.py` |
|---|---|
| `LLMRateLimitError` | Базовый класс для `GroqRateLimitError`. |
| `LLMSchemaError` | Базовый класс для `GroqSchemaError`. |
| `LLMPromptTooLargeError` | Базовый класс для `GroqPromptTooLargeError`. |
| `is_rate_limit_error` | В `_call_with_retry`, при перехвате сетевого исключения. |
| `is_request_too_large_error` | В `_call_with_retry`, при перехвате сетевого исключения. |
| `parse_retry_after` | В `_call_with_retry`, для `force_wait`. |
| `repair_json` | В `_parse_with_repair`, вторая попытка распарсить JSON. |
| `estimate_tokens` | Через `self._estimate_tokens(...)` — обёртка с коэффициентами из Settings. |
| `chars_per_token` | В `_auto_truncate_prompt`, чтобы перевести токен-бюджет обратно в символы. |

`LLMProviderOverloadedError` **не импортируется** `groq_client.py` — этот сценарий
(перегрузка апстрим-провайдера) характерен только для `OpenRouterClient`, у Groq
прямой доступ к собственной инфраструктуре без промежуточного роутинга моделей.

## Что дальше (Часть 3)

Следующая часть опишет вспомогательные классы `llm/groq_client.py`, не являющиеся
самим клиентом, но используемые им как компоненты:
- `TokenEstimateCalibrator` — адаптивная калибровка оценки токенов по роли;
- `CacheObservability` — диагностика попаданий в Groq prompt cache;
- `TokenRateLimiter` — клиентский TPM-лимитер (sliding window + leaky bucket +
  adaptive safety margin).

`generate_structured`).
