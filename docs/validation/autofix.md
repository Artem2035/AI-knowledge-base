# Документация: `validation/autofix.py` — автоисправление конфликтов путей

> Reference-док. Обзор пакета — `_index.md`.

**Назначение.** Детерминированный шаг БЕЗ LLM перед валидацией. Исправляет только то, что однозначно решается суффиксом « (2)», « (3)»…, чтобы ошибки путей не блокировали `approve`, когда причина тривиальна. Всё остальное (`update_missing_target`, `empty_body`, дубли путей у `update`) остаётся ошибкой валидации.

## `autofix_drafts(drafts: list[DraftNote], existing_paths: set[str]) -> tuple[list[DraftNote], list[ValidationIssue]]`

Правила:
1. `action=create` с путём, уже существующим в Vault (`existing_paths`), получает суффикс к заголовку и пути; ссылки `links_out` других заметок на старый заголовок **перенаправляются** на новый (аннотатор ссылался на заголовок из плана, то есть на нашу заметку, а не на чужой файл).
2. Два `create` на один путь внутри changeset: второй получает суффикс; ссылки **не** перенаправляются (однозначно выбрать цель нельзя, остаются на первую).
3. Свободный вариант ищется перебором `(2)…(99)` с учётом занятых путей и заголовков; не найден — черновик остаётся как есть (ошибку выдаст валидация).
4. `update` и «чистые» черновики не изменяются.

Исходный список и объекты не мутируются (`model_copy`). Каждое исправление даёт `ValidationIssue(level="warning", code="path_autofixed")`; эти предупреждения передаются в `run_validation(..., extra_issues=...)` и видны в diff.

| Имя | Тип | Назначение |
|---|---|---|
| `drafts` | `list[DraftNote]` | Черновики после слияния. |
| `existing_paths` | `set[str]` | `db.get_all_paths()`. |

**Возвращает:** `(новые черновики, предупреждения)`. **Исключения:** не поднимает.

**Место в потоке:** `Orchestrator.run()` — после слияния, до `apply_inline_links` и `build_moc` (они должны видеть итоговые заголовки).
